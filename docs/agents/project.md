# Project context

## Purpose and stage

Wistia PHP is a framework-independent PHP client distributed as `automattic/wistia-php` through Composer. It serves PHP applications integrating with Wistia. Usage scale is not established.

This is a library undergoing a breaking revival. P02 replaces the legacy magic client with shared configuration/execution/encoding/decoding/error primitives, declaring PHP `^8.4` with `ext-curl`, Guzzle `^8.2` and PHPUnit `^12.5`. P03 adds generic pagination adapters and the typed background-job-status operation with finite optional polling; P04 adds [OAuth helpers](../oauth.md) for authorization URLs, explicit code exchange and refresh. P05 adds [inbound webhook verification and parsing](../webhooks.md). P06 adds 19 [media lifecycle, tags, trims and deleted-media operations](../media.md), with typed nested results, local validation, pagination and asynchronous job handoff. P07 adds 24 [media customization operations](../customizations.md), with typed nested inputs/results, replacement and partial-update/null semantics, and offline contract coverage. P08 adds 16 [caption and accessibility operations](../accessibility.md): caption text formats and atomic versioned edits, speaker-profile reads, existing localizations and extended audio-description management/order-status reads, with offline contract coverage. P09 adds 17 [folder, sharing and subfolder operations](../folders.md), with nested typed inputs/results, local validation, pagination and asynchronous copy/bulk-delete handoff. P10 adds 16 [channel, collaborator and episode operations](../channels.md), with typed podcast inputs/results, publishing/scheduling validation and pagination. P11 adds ten [webinar, collaborator and registration operations](../webinars.md), with UTC schedule validation, nested updates, typed engagement results and filtered pagination. P12 adds nine [brand and account-branding operations](../brands.md), with explicit-null updates, application/inheritance options, pagination, preload selections and typed color-picker results. P13 adds 11 [account and access-management operations](../account.md), including usage, credits, allowed domains, invitations and experimental expiring tokens. P14 adds nine [search and review-sharing operations](../search-sharing.md), with metadata filters, typed grouped search results, resource URLs, bundle pagination and write-safe share links. P15 adds typed [non-purchasing bulk actions and jobs](../bulk.md), reusing resource payload contracts with local limits and shared partial-result job handoff. P17 adds all ten [Stats operations](../reference/stats.md), including account/media/date/engagement/event/visitor/project metrics, typed nested records and filtered offset pagination. P18 adds five [account Analytics operations](../reference/analytics.md), with exclusive-end date ranges, ranking filters and typed aggregate/timeseries/embed results. Other endpoint services and Upload workflows remain planned. Read [composer.json](../../composer.json), [src/Client.php](../../src/Client.php), and [README.md](../../README.md) for the actual foundation and its limitations. Historical live PHPUnit 4.8 tests remain preserved outside default discovery.

The agreed direction is a breaking rewrite for PHP 8.4+ and the supported server-side Wistia APIs, targeting 2.0.0. The approved specification is [#8](https://github.com/Automattic/wistia-php/issues/8); the [inventory](../rewrite/README.md) distinguishes planned endpoints from implemented foundation/helper coverage. The foundation alone does not satisfy whole-library acceptance or authorize release.

## Ownership and collaboration

The primary maintainer is the final product decision-maker. Agents own routine engineering within the requested scope; explain consequential choices in product terms and escalate scope, cost, security, and operating commitments.

Organization members retain repository admin access. External contributions are welcome through pull requests; outside contributors are not granted merge access. Administrators can change repository rules; PR requirements do not remove that capability.

## Constraints and risks

- Preserve package identity, existing license/copyright, and published history unless a separately approved change says otherwise.
- Consumers own their application hosting and integration; no platform-specific architecture is required.
- API credentials, uploads, media metadata, and webhook payloads may contain sensitive information. Keep credentials out of chat, logs, fixtures, and commits.
- Historical legacy tests can create/delete projects and upload media; their separately gated configuration must never be treated as a credential-free unit check. Default discovery selects only authored offline foundation, helper and contract tests.
- No Wistia test account or credentials have been supplied for this setup. Live API behavior is unverified.
- API changes, ambiguous write failures, account-plan restrictions, and charge-incurring operations require explicit contracts and meaningful checks during rewrite planning. Setup establishes none of those endpoint contracts.
- External automation is not fully known. Inspect affected integrations before changing branch, label, release, or API conventions.

Update this document when purpose, maintenance ownership, operating constraints, or confirmed revival scope changes; obtain approval for consequential changes.
