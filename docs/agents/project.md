# Project context

## Purpose and stage

Wistia PHP is a framework-independent PHP client distributed as `automattic/wistia-php` through Composer. It serves PHP applications integrating with Wistia. Usage scale is not established.

This is a library undergoing a breaking revival. P02 replaces the legacy magic client with shared configuration/execution/encoding/decoding/error primitives, declaring PHP `^8.4` with `ext-curl`, Guzzle `^8.2` and PHPUnit `^12.5`. P03 adds generic pagination adapters and the typed background-job-status operation with finite optional polling; P04 adds [OAuth helpers](https://wistia-php.space.fast/guides/how-to/oauth.html) for authorization URLs, explicit code exchange and refresh. P05 adds [inbound webhook verification and parsing](https://wistia-php.space.fast/guides/how-to/webhooks.html). P06 adds 19 [media lifecycle, tags, trims and deleted-media operations](https://wistia-php.space.fast/guides/how-to/media.html), with typed nested results, local validation, pagination and asynchronous job handoff. P07 adds 24 [media customization operations](https://wistia-php.space.fast/guides/how-to/customizations.html), with typed nested inputs/results, replacement and partial-update/null semantics, and offline contract coverage. P08 adds 16 [caption and accessibility operations](https://wistia-php.space.fast/guides/how-to/accessibility.html): caption text formats and atomic versioned edits, speaker-profile reads, existing localizations and extended audio-description management/order-status reads, with offline contract coverage. P09 adds 17 [folder, sharing and subfolder operations](https://wistia-php.space.fast/guides/how-to/folders.html), with nested typed inputs/results, local validation, pagination and asynchronous copy/bulk-delete handoff. P10 adds 16 [channel, collaborator and episode operations](https://wistia-php.space.fast/guides/how-to/channels.html), with typed podcast inputs/results, publishing/scheduling validation and pagination. P11 adds ten [webinar, collaborator and registration operations](https://wistia-php.space.fast/guides/how-to/webinars.html), with UTC schedule validation, nested updates, typed engagement results and filtered pagination. P12 adds nine [brand and account-branding operations](https://wistia-php.space.fast/guides/how-to/brands.html), with explicit-null updates, application/inheritance options, pagination, preload selections and typed color-picker results. P13 adds 11 [account and access-management operations](https://wistia-php.space.fast/guides/how-to/account.html), including usage, credits, allowed domains, invitations and experimental expiring tokens. P14 adds nine [search and review-sharing operations](https://wistia-php.space.fast/guides/how-to/search-sharing.html), with metadata filters, typed grouped search results, resource URLs, bundle pagination and write-safe share links. P15 adds typed [non-purchasing bulk actions and jobs](https://wistia-php.space.fast/guides/how-to/bulk.html), reusing resource payload contracts with local limits and shared partial-result job handoff. P17 adds all ten [Stats operations](../reference/stats.md), including account/media/date/engagement/event/visitor/project metrics, typed nested records and filtered offset pagination. P18 adds five [account Analytics operations](../reference/analytics.md), with exclusive-end date ranges, ranking filters and typed aggregate/timeseries/embed results. P19 adds seven [media Analytics operations](../reference/analytics.md#media-analytics-usage), with typed nested aggregate/timeseries/traffic/language results and bounded form-conversion cursor traversal. P20 adds five [webinar Analytics operations](../reference/analytics.md#webinar-analytics-usage), with typed polls/chats/histograms and bounded audience traversal. P16 adds five non-S3 [upload/import workflows](../reference/upload.md), with streamed files and operation-specific results. S3 copy remains unimplemented pending human response-contract confirmation; #24 remains incomplete. Read [composer.json](../../composer.json), [src/Client.php](../../src/Client.php), and [README.md](../../README.md) for the actual foundation and its limitations. Historical live PHPUnit 4.8 tests remain preserved outside default discovery.

The agreed direction is a breaking rewrite for PHP 8.4+ and the supported server-side Wistia APIs, targeting 2.0.0. The approved specification is [#8](https://github.com/Automattic/wistia-php/issues/8); the [inventory](../rewrite/README.md) distinguishes planned endpoints from implemented foundation/helper coverage. The foundation alone does not satisfy whole-library acceptance or authorize release.

## Public documentation

The approved documentation site covers the unreleased 2.0 API only. Reader-facing prose in `docs/site/` follows the maintainer-approved tutorial/how-to/reference/explanation structure, with separate framework integration guides and generated PHP API reference. It targets PHP developers familiar with Composer who are new to this client. Duplicate top-level usage guides have been removed; README sends users to the website. Keep `docs/site/` as its reproducible source, `docs/reference/` and `docs/rewrite/` as internal contract/evidence records, and example READMEs as exact consumer-setup instructions. Historical helper verification statements are retained in [helper evidence](../rewrite/helper-evidence.md). Keep milestone IDs and delivery-test/source evidence out of the public reading path. [Documentation tooling](../../tools/docs/README.md) owns build and publishing details. The site is credited to Automattic, uses its official branding and includes a “Hosted at Spacefast” footer. The initial destination is the maintainer's Spacefast account with a managed hostname; personal account ownership does not change attribution. Custom domains and ownership transfer are deferred. Paid upgrades and other deployments remain outside this approval.

## Ownership and collaboration

The primary maintainer is the final product decision-maker. Agents own routine engineering within the requested scope; explain consequential choices in product terms and escalate scope, cost, security, and operating commitments.

Organization members retain repository admin access. External contributions are welcome through pull requests; outside contributors are not granted merge access. Administrators can change repository rules; PR requirements do not remove that capability.

## Constraints and risks

- Preserve package identity, existing license/copyright, and published history unless a separately approved change says otherwise.
- Consumers own their application hosting and integration; no platform-specific architecture is required.
- API credentials, uploads, media metadata, and webhook payloads may contain sensitive information. Keep credentials out of chat, logs, fixtures, and commits.
- Historical legacy tests can create/delete projects and upload media; their separately gated configuration must never be treated as a credential-free unit check. Default discovery selects only authored offline foundation, helper and contract tests.
- The maintainer supplied a test account/token and explicitly approved small upload/import probes during P16. The [sanitized evidence](../rewrite/upload-evidence.md) records the limited standalone live observations; they are not live PHP-service or processing-completion verification. S3, broader API behavior and paid-plan entitlement remain unverified. The token stays in a private Git-ignored root `.env`; ordinary tests never load it. No standing authority for further live calls, purchases, setup or deletion follows.
- API changes, ambiguous write failures, account-plan restrictions, and charge-incurring operations require explicit contracts and meaningful checks during rewrite planning. Setup establishes none of those endpoint contracts.
- External automation is not fully known. Inspect affected integrations before changing branch, label, release, or API conventions.

Update this document when purpose, maintenance ownership, operating constraints, or confirmed revival scope changes; obtain approval for consequential changes.
