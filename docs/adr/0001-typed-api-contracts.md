# 0001: Explicit typed services with shared safe HTTP execution

**Status:** Accepted direction in [specification #8](https://github.com/Automattic/wistia-php/issues/8), recorded by P01 on 2026-10-15; implementation is not delivered by this record. The [inventory provenance](../rewrite/operations.json) pins the inspected agreement. No new product or architecture decision is made here.

The legacy client uses magic dispatch, generic query encoding, raw decoded values/error codes, Guzzle 6 and live integration tests. The approved breaking rewrite instead targets PHP `^8.4`, Guzzle `^8.2` and PHPUnit `^12.5`, retaining the `automattic/wistia-php` package, `Automattic\Wistia` namespace, license and published history. Explicit resource services and typed request/result objects make supported operations and endpoint-specific inputs/results discoverable without magic dispatch. Preserving the old PHP interface was an alternative explicitly excluded by #8; migration documentation, not a compatibility layer, is required.

Share HTTP execution, encoding, decoding, sanitized exceptions and rate-limit information instead of giving each resource inconsistent transport behavior. Keep endpoint-specific wire names, Data/Stats/Analytics's pinned `2026-09` version and Upload/OAuth's separate hosts/contracts rather than assuming one universal API. Guzzle is the approved transport dependency, not a new provider selection by P01. Separate offset, Data-cursor and Analytics-cursor responsibilities preserve their actual pagination semantics. Job polling is optional and finite; OAuth persistence/callbacks and webhook routing/processing remain consumer-owned.

No automatic retries or credential-bearing redirects: uniform replay is unsafe when writes may already have reached Wistia. Ambiguous writes must expose an uncertain remote outcome. Default tests must be offline with controlled HTTP responses; live/destructive checks retain separate gates. These choices trade implicit convenience and legacy compatibility for explicit behavior and observable failure boundaries. They do not authorize purchases, trials, automatic refresh/storage, endpoint implementation or live verification.

The [contract reference](../rewrite/README.md) explains downstream ownership, request/result mappings, restrictions and unresolved source discrepancies. Record a newly approved consequential change by superseding this ADR, preserving this rationale; do not silently turn missing Upload response evidence into a new public result design.
